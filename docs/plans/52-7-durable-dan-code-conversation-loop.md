# 52-7: Durable DAN Code Conversation Loop

**Parent:** [52-multicellular-composition](52-multicellular-composition.md)
**Status:** completed
**Goal:** Move `dan code` onto a durable orchestrator conversation loop so the shell can chat, clarify, launch bounded coding runs, and decide `continue / done / clarify` after validator-driven execution without leaving the universal-agent substrate.

## Tasks
- [x] 1. Add a reusable durable coding-conversation controller on top of the 52-6 runtime
  - [x] 1-1. Keep the orchestrator as a universal-worker agent backed by `DurableAgentRunner`
  - [x] 1-2. Teach the orchestrator to classify user turns as `respond`, `clarify`, or `code`
- [x] 2. Route bounded coding results back into the durable orchestrator
  - [x] 2-1. Review each bounded coding report through the same orchestrator session
  - [x] 2-2. Let the orchestrator decide `done`, `continue`, or `clarify` after validation instead of treating validator output as the final authority
- [x] 3. Update the DAN Code product shell to persist the durable conversation state
  - [x] 3-1. Persist conversation messages and pending clarification in `.dan-code/session.json`
  - [x] 3-2. Add `/clear` as a real conversation reset alias
- [x] 4. Lock the new shell behavior with focused CLI regressions
- [x] 5. Tighten the module seams so the shell stays stackable as building blocks
  - [x] 5-1. Move transient LLM API retry logic into the shared provider layer instead of the `dan code` control loop
  - [x] 5-2. Replace loose CLI/orchestrator dict payloads with explicit conversation-context and bounded-run-summary contracts
  - [x] 5-3. Relax the orchestrator intent guard so ambiguous non-task turns stay conversational instead of accidentally triggering the coding worker pool
  - [x] 5-4. Add one shared runtime/session facts packet that both local CLI answers and orchestrator prompts can use for workspace/status context
  - [x] 5-5. Tighten post-run review so failed or no-output build-style runs cannot be marked done
  - [x] 5-6. Remove regex/local natural-language shell shortcuts so the orchestrator answers status/workspace/result questions from shared facts and recent report context
  - [x] 5-7. Stop resumed orchestrator turns from inheriting stale worker-core continuation, and unwrap nested completion JSON before turn/review normalization
  - [x] 5-8. Normalize plain-text or partial orchestrator outputs into safe `respond` / `continue` decisions instead of silently defaulting them to `code`

## Decisions
- `dan code` still uses the dedicated bounded coding organism for heavy implementation work; the new durable layer wraps that organism rather than replacing it.
- Only explicit slash commands stay local shell behavior. Natural-language status/workspace/result turns now go through the durable orchestrator, which answers from shared facts and recent report context instead of a regex shortcut layer.
- The orchestrator is the public voice and decision-maker; worker/validator outputs are evidence routed back into it.
- The intended module stack is explicit and thin: `provider wrapper -> durable orchestrator -> bounded coding organism`. Each layer should only know the narrow contract of the layer below it.

## Notes
- `src/dan/worker/organisms/coding_conversation.py` is the new reusable durable control-plane helper for the coding shell.
- `src/dan/cli/code.py` now persists conversation state, routes ordinary turns through the durable orchestrator, and only launches the bounded coding organism when the orchestrator chooses `code`.
- After each bounded coding run, the CLI sends a structured report summary back to the same orchestrator session so it can decide whether to stop, continue with one more bounded pass, or ask a clarifying question.
- `src/dan/providers/retrying_provider.py` now keeps transient LLM API retries in the shared provider layer, so Kimi/OpenAI-compatible failures can recover without baking retry loops into the orchestrator or CLI.
- `src/dan/worker/organisms/local_runtime.py` now treats raw `shell_command` as mutation-capable when deriving read-only tool baskets, so worker/validator roles cannot sneak filesystem writes through shell heredocs or `mkdir` while the aggregation/write phase remains the only full-mutation layer.
- `ToolLoopCompletionProvider` and the DAN Code product config no longer impose an 8-round tool-loop cap by default. `max_tool_rounds` is now optional across the CLI/config/runtime seam, so long coding turns only hit a round limit when the operator explicitly sets one.
- `ToolLoopCompletionProvider` now also injects one shared local tool-use policy for structured tools. That keeps the local-runtime seam reusable across organisms while steering models toward `list_directory` / `file_read` / `file_write` / `web_search` / structured git tools before shell fallbacks, and the coding organism now reinforces that same preference plus non-overlapping discovery in its role instructions.
- The durable controller and organ layers now share a tolerant structured-payload parser (`src/dan/worker/structured_payload.py`), so fenced JSON and leading-prose JSON-ish replies no longer silently degrade into raw assistant text or organ output-contract failures. The coding build/aggregation/validator organs also now allow extra output keys while still requiring the core contract fields.
- The durable orchestrator now also unwraps embedded structured payloads that accidentally land inside fields like `public_response`, so a model reply that nests a fenced JSON decision inside another JSON object no longer leaks that raw blob to the CLI.
- The durable session layer now also has its own freshness boundary. `.dan-code/session.json` carries a session-format/runtime-build stamp, strips bulky `outputs` / `trace_rows` from persisted turns, and clears saved conversation/pending-clarification/orchestrator state when the loaded session predates the current runtime so restart-after-patch sessions do not inherit stale hidden controller memory.
- The worker core now has one reusable structured-output enforcement seam as well. When an `OutputContract` includes `output_schema`, `WorkerCoreExecutor` injects the JSON schema into the prompt, validates the returned payload, and runs one generic repair-only completion pass before surfacing a structured-output failure. `coding_conversation.py` is the first DAN Code layer to opt into that seam for turn/review decisions, so controller routing depends less on prompt-only JSON discipline.
- The shared local tool seam now also includes `file_edit`, a targeted line-based mutation tool for existing files. DAN Code’s default local basket, mutation/risk classification, and local tool-use policy now treat `file_edit` as the preferred precise-edit primitive, while `file_write` remains the whole-file create/replace/append primitive.
- The shared local tool seam now also includes `web_search` in the default live basket, so local coding organisms can do lightweight external lookup without extra `--tool web_search` wiring. Because it stays in the read-only subset, workers and validators can search the web without gaining extra mutation authority.
- The standalone file tools now accept `file_path` as a compatibility alias for `path`, which removes a low-signal source of failed local tool calls from real `dan code` transcripts.
- Aggregation/output-contract failures now preserve any material candidate fields they did produce (`candidate_id`, `change_summary`, `target_files`, `test_plan`) instead of collapsing the run to `files=(none)`. That lets the durable orchestrator and final CLI report say “the run failed after producing partial output” rather than pretending nothing happened.
- The CLI/orchestrator seam is now typed through `CodingConversationContext` and `CodingConversationReportSummary` instead of ad hoc dict payloads, which keeps the control-plane diagrammable as small reversible modules.
- The orchestrator intent guard now prefers `respond` / `clarify` whenever the user has not actually supplied a direct actionable repo/coding task, which keeps short chat/meta turns inside the durable orchestrator layer instead of letting them slip into a bounded coding run because of rigid default-to-code behavior.
- `CodingConversationFacts` is now the shared runtime/session facts packet. `dan code` uses it for slash-command status output and for durable orchestrator prompts, so questions like current working directory or current status have one central source of truth instead of one-off CLI strings or regex-matched local replies.
- Recent-report context is now filtered as well. Failed no-output runs stay visible in latest-report facts for honest status answers, but the controller’s resumable/carry-forward report context only includes reports that actually produced material output, so malformed/fallback continuation turns do not auto-loop on empty failures.
- The orchestrator contract now explicitly tells the model to resolve references like `the website we talked about` against recent conversation/report context and to clarify when the reference is still unresolved. The review contract also now forbids `done` when a build-style run failed or produced no concrete material output.
- The durable orchestrator now opts out of worker-core continuation reuse for turn/review decisions. It relies on explicit `recent_conversation`, `recent_reports`, and `CodingConversationFacts` instead of silently inheriting stale acquisition context from the previous turn, which prevents resumed sessions from treating meta questions like `current status?` as if they were continuations of an earlier coding task.
- `_parse_payload(...)` now unwraps the worker-core `{"text": ..., "result": ...}` completion envelope before model-validating the orchestrator decision. Without that, the Pydantic defaults could silently turn a valid JSON response into `action=code`.
- Turn/review normalization now infers safe actions when the orchestrator returns partial payloads. A plain `public_response` now normalizes to `respond` for user turns and to `continue`/`done` for review turns based on the bounded run state, which prevents vague or plain-text meta-turn replies from silently launching the coding organism.
- User-turn normalization now also upgrades question-like `respond` payloads into `clarify`, so when the orchestrator asks the user to choose the next step or supply missing info, the shell persists that clarification state instead of clearing it and losing the thread on the next short follow-up.
- The user-turn safety fallback is now context-aware for continuation requests, but only when the session has a recent report that actually produced material output. Empty failed reports no longer seed automatic retry loops if the orchestrator reply flakes out.
- The bounded coding organism now defaults fallback fan-out to one worker unless the orchestrator explicitly asks for more or supplies multiple distinct briefs, which keeps malformed or missing `worker_count` payloads from silently fanning narrow tasks back out to two workers.
- The universal validator inside the DAN Code path now resolves 1-1 reviewer ties conservatively to `repair`, and the local aggregation phase now refuses to treat claimed concrete `target_files` as real candidate output unless the write-capable aggregation step shows mutation-capable tool evidence.
- `CodingOrganismReport` now owns the CLI/session normalization for `target_files`, `test_plan`, and `risks`, including repairing old saved character-split sessions. The coding runtime intentionally does not push one shared `output_schema` onto whole coding-organism boundary packets because validator reviewer members and lead cells return different shapes.
- The coding organism now also normalizes candidate packets through the shared `src/dan/worker/outcomes.py` module before live events, salvage paths, and aggregation gating use them. That shared seam owns structured-outcome normalization, char-split/multiline repair, and `modified|verified` execution-effect inference, so verification-only/no-op passes can still carry `target_files` and `test_plan` evidence without tripping the mutation-evidence guard that is reserved for claimed workspace changes.
- `universal_validator_organ(...)` now accepts an explicit `review_tie_break_priority` contract instead of baking the conservative `repair` preference directly into one preset body. DAN Code still passes `["repair", "pass"]`, but the policy is now reusable and overridable by other organisms.
- Transcript-driven follow-up hardening now also keeps the local runtime honest about git availability, so DAN Code no longer offers structured git tools when the workspace is outside a repository and the shared tool-use policy explicitly tells the model not to fall back to shell `git` commands there.
- The shared tissue quorum extractor now normalizes longer verdict strings back onto the configured tie-break vocabulary, and the coding-plan normalizer now collapses duplicate worker briefs back to one worker instead of silently keeping narrow tasks fanned out.
- `--show-model-trace` now rides the shared provider streaming seam instead of just printing final previews after completion. Text-only replies from both the local tool loop and the durable orchestrator controller emit explicit `model.stream.*` events, and tool-enabled local-runtime rounds now also keep streaming because completed `StreamChunk` payloads preserve final tool calls, finish reasons, and raw assistant messages for the local tool loop. The CLI renderer still falls back to a final preview when a streamed turn completes without visible deltas.
- The durable coding-conversation layer now keeps one accountable mailbox path for ordinary turn/review decisions. Explicit coding turns and completed post-run reviews still go through the durable orchestrator session, while latency optimization stays in reusable lower seams such as bounded provider hedging instead of controller-level bypasses.
- The same durable control layer now also uses a bounded hedge for real no-tool controller decisions. When a turn/review decision still needs an LLM call, it can launch one secondary provider completion after a short delay and accept the first response that already satisfies the shared structured-output schema; the write-heavy coding organism remains unchanged.
- 2026-04-11 follow-up: the DAN Code stack is now tighter around the “universal agent + thin top-level connector” target. Explicit coding turns and completed post-run reviews now also stay on the durable orchestrator mailbox path instead of controller-local fast paths, `coding_conversation.py` and `coding_execution.py` share one `build_coding_orchestrator_worker(...)` factory, child stage packets inherit parent budget/authority/continuation/reply-hook membrane state, and final coding completion now requires the selected candidate to meet the selected `pass_threshold` instead of trusting a bare validator `passed=true` verdict.
- Bounded coding runs now also persist a product-level step log under `.dan-code/runs/turn-XX/events.jsonl`. That stream records timestamped lifecycle/status/tool/public-assistant events through the same shared event-callback seam the CLI renderer uses, and the final report/transcript keep an `event_log_path` pointer back to that file for later analysis.
- The shared local file-tool seam is now more honest about performance too. `file_write` remains the cheap whole-file append/overwrite primitive, `file_edit` remains a deliberate full-file rewrite for predictable line-based edits, and `file_read` now streams requested line windows before applying the large-file guard so bounded reads on big files do not pay whole-file cost or fail with contradictory guidance.
- The next narrow speed pass stayed inside that same seam instead of introducing a new runtime path. `file_edit` now accepts `edits=[...]` for multiple non-overlapping same-file edits in one read/write pass, and the shared local tool-use policy tells models to prefer that form when they would otherwise emit several single-file edit calls in a row.
- The validator surface is also less brittle at the shared tissue seam now. Review-quorum vote extraction falls back to the first tie-break priority for non-empty malformed completed prose, while blank/missing vote text still stays outside the counted votes so true missing reviewer outputs continue to escalate instead of being papered over.
- 2026-04-15 follow-up: [53-dan-code-project-planner-loop](53-dan-code-project-planner-loop.md) inserted a sibling durable project-planner layer above the bounded coding organism, so broader DAN Code requests can be narrowed into persisted milestone slices before the existing bounded repair loop runs.
